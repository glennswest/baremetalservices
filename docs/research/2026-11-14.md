# Research 2026-11-14 (baremetalservices, #628)

Scope: since 2026-11-07. Read-only; no code changed. No third-party Go deps (`go.mod`); upstream risk is the image inputs in `pxeimage/build.sh` (Alpine v3.20 packages and linux-lts, Debian trixie glibc, mlxup/CX3 firmware).

## 1. Upstream
- Nothing new that changes last week's finding: **Alpine v3.20 is still the pinned repo and is EOL** (#33, open P2).
- Alpine 3.21 also reached end of support on 2026-11-01 ([roundup](https://www.linuxcompatible.org/story/linux-security-roundup-alpine-ssh-flaw-and-shared-apt-bug/)), so 3.22 or 3.23 (or 3.24) are the targets; not 3.21.
- Recent Alpine point releases 3.21.9 / 3.22.7 / 3.23.7 / 3.24.3 carry a musl regex heap overflow and zlib heap overflow fix ([report](https://www.linuxcompatible.org/story/alpine-3219-3227-3237-and-3243-security-releases-patches-critical-php-rce/)). The image's musl and zlib come from v3.20 and get none of them. Supports #33.
- Alpine 3.23 and 3.24 ship the **Linux 6.18 LTS** kernel ([3.23](https://linuxiac.com/alpine-linux-3-23-released-with-linux-kernel-6-18/), [3.24](https://www.linuxpromagazine.com/Online/News/Alpine-Linux-3.24-Features-Fresh-Desktops-and-a-Newer-Kernel/(tagID)/154)); v3.20 is 6.6. Moving is a kernel jump 6.6 -> 6.18: module list, firmware and the `KVER` derived in build.sh need re-checking, and the QEMU boot test is the gate.
- No smartmontools, ipmitool or efibootmgr advisory found for this window. No November Alpine linux-lts advisory found (searched; Alpine's own tracker not read).
