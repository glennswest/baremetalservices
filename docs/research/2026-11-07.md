# Research 2026-11-07 (baremetalservices, #628)

Scope: since 2026-10-13. Read-only; no code changed. Go module has no third-party deps (`go.mod`), so
upstream risk is the image inputs in `pxeimage/build.sh`: Alpine v3.20 packages, linux-lts, Debian trixie glibc, mlxup/CX3 firmware.

## 1. Upstream
- **Alpine v3.20 is end of life** (since 2026-04-01 per [endoflife.date](https://endoflife.date/alpine-linux), [endoflife.ai](https://endoflife.ai/alpine-linux/3.20)).
  `build.sh` lines 43-44 pull `main`/`community` from `alpine/v3.20`, including `linux-lts`, so the image's kernel and
  userland (smartmontools, nvme-cli, efibootmgr, ...) get no security fixes. Supported: 3.22 (to 2027-05-01), 3.23 (to 2027-11-01),
  3.24 branched 2026-06-09 ([release branches](https://alpinelinux.org/releases/)). -> issue filed (P2).
- Kernel 6.12 LTS: Debian shipped 6.12.111 on 2026-10-04 ([DLA-4817-1](https://linuxsecurity.com/advisories/deblts/debian-lts-dla-4817-1-linux-6-12)),
  a batch of privilege-escalation/DoS/leak CVEs. Whether this matches the Alpine 3.20 linux-lts version was not checked
  (3.20 ships 6.6 LTS, now frozen); covered by the Alpine bump above. No RUSTSEC/npm items (no such deps).
- Debian trixie glibc runtime is fetched at build time; no advisory specific to it found this window.
- mlxup / CX3 firmware are pinned by sha256; no new release looked at.

## 2. Specs
- Nothing new found for IPMI 2.0, UEFI boot-order (efibootmgr) or Supermicro `sum` that changes the API.

## 3. Techniques for open issues
- **#32 (BMC reset reverts login):** cause is in `main.go` `handleIPMIReset`: it runs `ipmitool user set name 2 ADMIN` /
  `user set password 2 ADMIN`, i.e. it writes the factory login itself. Fix is to read the configured login from stormcentral and
  set that instead (or only restart with `mc reset cold`, which keeps config: [One Identity KB](https://support.oneidentity.com/kb/259242/ipmi-reset),
  [Thomas-Krenn](https://www.thomas-krenn.com/en/wiki/IPMI_BMC_reset_for_IPMI_problems)). Supermicro's factory restore can preserve
  users in the web UI ([FAQ 16441](https://www.supermicro.com/es/support/faqs/faq.php?faq=16441)); `ipmicfg -fd` deletes all users
  ([Thomas-Krenn ipmicfg](https://www.thomas-krenn.com/en/wiki/IPMI_configuration_for_Supermicro_servers_with_ipmicfg)).
  Vendor raw codes (`0x30 0x40`, `0x3c 0x40`) are unverified on X9: test on a spare blade.
- **#31 (ACPI power button):** a busybox `acpid` (or init reading `/dev/input/event*` power-button) running `poweroff` is the usual
  approach on Alpine; busybox acpid is in the Alpine main repo.
- **#30 (SMART as numbers):** `smartctl -x -j` JSON is stable across smartmontools 7.x; ATA attributes are under `ata_smart_attributes.table`, NVMe under `nvme_smart_health_information_log`.
